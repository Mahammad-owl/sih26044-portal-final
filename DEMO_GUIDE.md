## 3. Deep-Dive Q&A Guide for Technical Judges

### Q1: "Can a brand new student register, or is this only a static demo?"

  5. Show that Rohan is genuinely created in SQLite, his profile is initialized, and the Onboarding Wizard welcomes him!

### Q2: "Where is the data stored? Does it persist across reloads?"
* **Demonstration**:
  - Show the SQLite database file at `database/sih_portal.sqlite`.
  - Explain that all users, skills, verifications, opportunities, and applications are stored in 22 relational tables with foreign keys and ACID transactions.
  - Refresh the browser or run queries directly in the terminal to prove data persistence.

### Q3: "How does the matching engine work? Is it real or fake?"
* **Answer**:
  - It is a deterministic mathematical engine implemented in `backend/services/matchingEngine.js` and `src/context/AppContext.tsx`.
  - It computes the weighted sum:
    $$\text{Match} = \text{Skill Alignment (60\%)} + \text{Assessment Score (20\%)} + \text{Project Evidence (10\%)} + \text{Coursework (10\%)}$$
  - Missing mandatory skills severely penalize the score, while verified evidence awards full weight.

### Q4: "Why did you avoid external AI APIs like ChatGPT?"
* **Answer**:
  - Hackathons require 100% offline reliability. Paid cloud APIs introduce network latency, quota limits, and privacy issues with student data.
  - More importantly, recruiters do not want "AI hallucinations" in hiring decisions—they want **verifiable proof**. Our deterministic multi-stage verification and transparent matching provide 100% auditability.
